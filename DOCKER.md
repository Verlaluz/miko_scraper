# Docker Deployment Guide — miko_scraper

> **Branch:** `docker` — test here before merging to `master`.

## Architecture

```
Host (Windows)              Docker Container
─────────────────           ─────────────────────────────────
./data/                 ──► /app/data/
  miko_scraper.db               miko_scraper.db  ← SQLite reads/writes here
.env                    ──► injected as env vars (never baked in image)
localhost:3000          ◄── container:3000
```

The binary is compiled **inside** the Docker builder stage (Linux, x86_64), so there's no cross-compilation needed on Windows.

---

## First-Time Setup

### 1. Install Docker Desktop
Download from https://www.docker.com/products/docker-desktop/ and make sure Docker is running.

### 2. Copy your database into the `data/` directory

```powershell
# Windows PowerShell
mkdir data
copy miko_scraper.db data\miko_scraper.db
```

> **Why?** The `docker-compose.yml` mounts `./data` → `/app/data` inside the container.
> This means your 55+ phone accounts and all sessions are preserved and survive container restarts.

### 3. Build and start

```powershell
docker compose up --build
```

The first build takes **5–10 minutes** (compiling all Rust dependencies). Subsequent builds are fast because Docker caches the dependency layer.

### 4. Verify it works

Open http://localhost:3000 — you should see the dashboard.

## Environment Variables

`docker-compose.yml` loads your `.env` file automatically, then overrides two variables:

| Variable | Native value | Docker value | Why |
|---|---|---|---|
| `SERVER_HOST` | `127.0.0.1` | `0.0.0.0` | Container must listen on all interfaces |
| `DATABASE_URL` | `sqlite:miko_scraper.db` | `sqlite:/app/data/miko_scraper.db` | DB is in the mounted volume |

You **do not** need to edit your `.env` file for Docker. The overrides happen in `docker-compose.yml`.

## Common Commands

```powershell
# Start in background (detached mode)
docker compose up -d --build

# View logs
docker compose logs -f

# Stop the container
docker compose down

# Stop and remove everything (volumes are kept separately)
docker compose down --volumes

# Rebuild after code changes
docker compose up --build
```

## GitHub Actions deployment

The `Miko Scraper CI/CD` workflow builds the production image on pull requests
and pushes to `master`. A production deployment runs after a successful build
when the repository environment contains these secrets:

- `DEPLOY_HOST` — deployment server hostname or IP
- `DEPLOY_USER` — SSH user
- `DEPLOY_SSH_KEY` — private key accepted by that user
- `DEPLOY_PATH` — absolute path of this checkout on the deployment server

The deployment keeps `.env` and `data/` untracked, backs up the SQLite database,
rebuilds the image, and waits for the container health check to pass. The
Telegram token and database must be configured on the deployment server; they
are never stored in GitHub Actions.

## Database Safety

- `miko_scraper.db` is **never committed to git** (`.gitignore` excludes `*.db`)
- The `data/` directory is also gitignored
- The database file lives on your host machine at `./data/miko_scraper.db`
- Docker just mounts it — if you delete the container, your data is safe

## Troubleshooting

### "Port 3000 already in use"
Your native `miko_scraper.exe` is still running. Either stop it first, or change the host port in `docker-compose.yml`:
```yaml
ports:
  - "3001:3000"   # access via http://localhost:3001
```

### "miko_scraper.db not found"
Make sure you copied the DB file: `copy miko_scraper.db data\miko_scraper.db`

### Build fails with sqlx error
The `.sqlx/` directory (generated by `cargo sqlx prepare`) must be committed.
Run: `cargo sqlx prepare` then `git add .sqlx`
